## Что готово и закоммичено

- **MinIO** — файлы (фото кроликов) хранятся в S3-совместимом MinIO вместо
  локального диска, отдаются через прокси-роут API. Живая проверка через
  докер-стек пройдена (upload → fetch → delete → 404).
- **Эсхата Мерчант** — платёжный клиент (подпись SHA-256, dynamic-kassa,
  создание заказа + проверка статуса), модель `Payment` (tenant-scoped),
  сервис `paymentService` (webhook никогда не доверяется без перепроверки
  подписанным запросом к банку), контроллер, роуты. **Живьём проверено**
  против тестового контура банка (create + status — реальные ответы банка).
- **Payom SMS** — транспорт для шаблонных SMS, templateId берётся из
  конфига (`SMS_TEMPLATE_IDS`), не хардкодится. Постоянные ошибки
  (401/403/422) не ретраятся, временные (429/5xx/сеть) помечены retryable.
  **Реальная отправка подтверждена живьём** (2026-09-07): IP разработчика
  добавлен в вайтлист Payom напрямую (не через Tailscale — обычная сеть),
  SMS дошла на реальный номер, `deliveryStatus: SERVICE_ACCEPTED`. Шлюз
  требует номер строго в формате `+992XXXXXXXXX` (с `+`, 13 символов) —
  без плюса 422. Для повторной ручной проверки: `backend/scripts/test-payom-sms.js`.

## Известное ограничение окружения

Эсхата (`connecttest.eskhata.com`) банит доступ по IP с обычной сети
разработки — живая проверка сделана через Tailscale exit node (`honor-win`):
включить `tailscale set --exit-node=<name>`, выключить после
`tailscale set --exit-node=`. Payom (`gateway.payom.tj`) банил так же, но
решается проще — обычный вайтлист IP в кабинете Payom, без обхода через VPN.
IP разработчика похож на динамический (менялся в пределах одной сессии) —
если снова словите 403 с `IP-block`, вайтлист нужно обновить на актуальный.

Корпоративный Kaspersky Endpoint Security на рабочем Windows-ноуте блокирует
(рвёт TLS-хендшейк, `ECONNRESET`/`errno=10053`) любой трафик к почтовым
доменам напрямую с Windows — не помогает ни VPN, ни вайтлист IP в Stalwart
(IP не был забанен). Это блокировка на уровне антивируса, а не сети или
сервера. Обход: гонять SMTP-запросы из WSL2 (`wsl -d FedoraLinux-42 -- ...`)
— виртуальная сеть WSL2 не перехватывается тем же модулем антивируса,
TLS-хендшейк и живая отправка проходят нормально. Заодно выяснилось, что
порт 587 (STARTTLS) у `mail.mubi.dev` не отвечает вовсе (timeout) — рабочий
порт 465 (implicit TLS/SMTPS), см. `backend/src/config/mailer.js`.
