# Handoff: состояние на 2026-09-07

Кратко — что сделано, что настроено локально и не попало в git, что дальше.
Пишется для продолжения работы с другого устройства.

## Что готово и закоммичено

- **MinIO** — файлы (фото кроликов) хранятся в S3-совместимом MinIO вместо
  локального диска, отдаются через прокси-роут API. Живая проверка через
  докер-стек пройдена (upload → fetch → delete → 404).
- **Эсхата Мерчант** — платёжный клиент (подпись SHA-256, dynamic-kassa,
  создание заказа + проверка статуса), модель `Payment` (tenant-scoped),
  сервис `paymentService` (webhook никогда не доверяется без перепроверки
  подписанным запросом к банку), контроллер, роуты. **Живьём проверено**
  против тестового контура банка (create + status — реальные ответы банка).
- **Payom SMS** — транспорт для шаблонных SMS, templateId берётся из
  конфига (`SMS_TEMPLATE_IDS`), не хардкодится. Постоянные ошибки
  (401/403/422) не ретраятся, временные (429/5xx/сеть) помечены retryable.
  Формат запроса подтверждён живьём (легитимный 403 IP-block от Payom —
  значит токен/формат верные), но **реальная отправка SMS ещё не сделана**
  — упирается в тот же IP-фильтр банка/шлюза, что был у Эсхаты.
- **Тесты**: 1200/1200 зелёных, 69/69 сьютов. Попутно найден и исправлен
  реальный кросс-платформенный баг — `testDb.js` дёргал
  `node_modules/.bin/sequelize-cli` (shell-shim), что падает с ENOENT на
  Windows и никогда не ловилось в CI (CI на ubuntu-latest). Теперь миграции
  тестовой БД запускаются через `node` напрямую по JS-файлу пакета.

## Настроено локально, НЕ в git (перенести на другое устройство вручную)

`backend/.env` (гитигнорится) содержит реальные тестовые креды:
- `ESKHATA_*` — тестовый контур банка (id организации, merchID, hash key).
- `SMS_API_TOKEN` — реальный токен Payom, `SMS_TEMPLATE_IDS` — маппинг
  `user.verification_code` → готовый templateId.

Актуальные плейсхолдеры и комментарии — в `backend/.env.example`. Значения
самих секретов у пользователя (не хранятся в репозитории намеренно).

## Известное ограничение окружения

И Эсхата (`connecttest.eskhata.com`), и Payom (`gateway.payom.tj`) банят
доступ по IP с обычной сети разработки. Живая проверка Эсхаты сделана через
Tailscale exit node (`honor-win`) — включить: `tailscale set --exit-node=<name>`,
выключить после: `tailscale set --exit-node=`. Для Payom этот обход пока не
пробовали — тестовая отправка SMS на реальный номер ожидает решения.
