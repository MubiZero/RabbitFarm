# Действия без последствий: что закрыто и что осталось

Разбор от 14–15 сентября 2026. Приложение прочитали насквозь на один вопрос:
где интерфейс обещает то, чего не делает — кнопка без последствий, поток,
оборванный на полпути, поле, которое человек заполняет в пустоту.

Этот файл — рабочая карта: сверху закрытое (чтобы не искать заново), снизу
незакрытое с ценой и объяснением, почему это важно.

## Закрыто

### Сломано было полностью

| Что | Суть |
|---|---|
| Отметка падежа | Приложение слало статус `deceased`, сервер принимает только `dead` — 422 на каждую попытку. Без связи запись вдобавок выбрасывалась из очереди как «неисправимая», а человеку показывали «сохранено». Слово теперь одно на всё приложение, контракт закрыт тестами с обеих сторон |
| Экран замка | Подсказка к кнопке требует слоя поверх навигатора, а `PinGate` рисуется над ним — вместо клавиши «стереть» была красная плашка Flutter. Подпись перенесена в `Semantics` |
| Ферма с истёкшим тарифом не могла заплатить | Сервер сам переводит её в режим чтения, а тот режет все не-GET запросы. Кнопка «Оплатить» отвечала 403 «обратитесь в поддержку». Оплата и регистрация пуш-токена переведены на `authenticateEvenIfFarmBlocked` |
| Квитанция об оплате | Вызов передавал `{title, body}`, функция ждала `{key, params}` — падало на каждом платеже, ошибка уходила в лог. Ни одной квитанции не было отправлено ни разу |
| Отказ банка | Статус `failed` не писался ни в одной ветке: человек бесконечно жал «Проверить оплату» и читал «ещё не подтверждено». Добавлен словарь признаков отказа; незнакомое слово банка отказом не считается и пишется в лог, чтобы словарь пополнялся по факту |

### Оборванные потоки

- **Поддержка.** Была дорогой в один конец: человек писал и не узнавал ничего.
  Появились `answer`/`resolved_by`/`resolved_at`, ответ уходит автору пушем и
  письмом, у фермы есть список своих обращений. В админке — окно ответа при
  закрытии и **форма контакта поддержки**: задать телефон и почту было нельзя
  вообще, поэтому блок «свяжитесь напрямую» не показывался никому никогда.
- **Приглашение сотрудника** только создавало запись в базе. Теперь уходит
  письмо; для телефона владелец получает ссылку-приглашение и копирует её
  (одобренного шаблона SMS под приглашение у шлюза нет — см. ниже). Появились
  просроченные приглашения отдельной группой и «Пригласить заново».
- **Лента уведомлений.** Единственным каналом был пуш: он пропадает со шторки,
  а до отказавшего в разрешении не доходит вовсе. Сообщения теперь ложатся в
  ленту **до попытки отправки и независимо от неё**; текст собирается на языке
  читателя в момент чтения. Побочно: объявления платформы стало можно
  перечитать.
- **Разрешение на уведомления** спрашивалось холодным системным диалогом сразу
  после входа. Теперь сначала свой экран с объяснением выгоды, и только после
  согласия — системный.

### Главный рабочий цикл фермы

- **Прощупывание** и **отсадку** негде было записать, хотя сервер, карточки и
  лента цикла на них построены: пустая самка оставалась в плане окролов и
  получала маточник.
- **Автозадачи не закрывались делом** — записал окрол, а «прощупать» и
  «ожидать окрола» висели просроченными вечно и каждое утро уходили пушем.
  Теперь закрываются событием (`services/autoTaskService`); задачу, заведённую
  человеком руками, событие не трогает.
- **Просроченные прививки** считались строками истории: «просрочено 40» на
  ферме из восьми кроликов. Теперь считаются животными
  (`utils/vaccinationDue`), повторная прививка снимает просрочку, павшие не
  считаются.
- **Закупка корма** не попадала в расходы — а это обычно главная статья затрат.
  Спрашиваем стоимость: «добавил» значит и «закупил мешок», и «пересчитал».

### Разное

- **Отмена удаления** вместо диалога «Удалить?» на 15 экранах: запрос уходит
  через несколько секунд, «Вернуть» отменяет его вовсе.
- **Подтверждение сдвигом** на необратимом (отметка падежа) — против случайного
  касания в перчатке.
- **Форма кролика**: три поля в главном блоке вместо одиннадцати подряд,
  остальное под «Дополнительно». Пол больше не выбран заранее.
- **Размеры под перчатки**: `AppSizes` (56/64) вместо 44–48.
- **Права**: уборка клетки доступна работнику (сервер её и не запрещал),
  управляющий получил `viewStaff` отдельно от `manageStaff`.
- **Отчёты**: породы считались вместе с павшими рядом с «поголовьем» из живых;
  лечения шли за всё время рядом с прививками за период.
- **Журнал фермы** теперь пишет удаления — кто и что стёр.
- **Журнал админа** называет людей и фермы по именам, а не «Админ №3 · Ферма №7».
- **Клетка как точка входа**: завести нового кролика прямо в клетку, покормить
  клетку, QR-метки на клетках (печать листа и чтение камерой).
- **Голосовой ввод** в полях свободного текста.
- **Печать плана окролов** на месяц.
- **Узбекские апострофы** приведены к орфографии (`ʻ` U+02BB в `oʻ`/`gʻ`, `ʼ`
  U+02BC в гортанной смычке) — 417 строк; сторожит тест
  `test/l10n/uzbek_apostrophes_test.dart`.

## Осталось

По убыванию пользы. Все пункты подтверждены чтением кода.

1. **Исполнитель задачи и автор проводки** `S+S`. Сервер отдаёт
   `assignedTo: {id, full_name}` в каждом ответе по задачам, модель разбирает
   только число, ни один экран исполнителя не показывает. Назначить задачу
   работнику из приложения нельзя вовсе, хотя сервер это полностью поддерживает
   и шлёт исполнителю личный пуш. То же с автором прихода/расхода: сервер
   отдаёт `creator`, книга денег его не показывает — а для фермы с наёмным
   управляющим это главный вопрос к денежной странице.
2. **Продажа кролика без прихода в книге** `M`. Связь работает в одну сторону:
   завёл приход категории `sale_*` — кролик станет «продан». Обратно нет:
   поставил статус «Продан» — ни прихода, ни `sold_date`.
3. **Мёртвые поля** `S` каждое. Человек их заполняет, приложение больше нигде
   не показывает: нрав кролика, дата приобретения, чек операции (`receipt_url`),
   доза лекарства, размер клетки, дата съёмки фото. Стоимость прививки хуже
   прочих: поля нет в модели приложения вовсе, поэтому автоматика
   «прививка → расход» не срабатывает ни разу, хотя для лечения такая же
   работает.
4. **Назначение кролика** (мясо/племя/продажа) `M` — только фильтр списка.
   Решение по нему обсуждалось: перенести на уровень фермы в знакомство и
   оттуда подставлять в форму умолчанием, потому что большинство ферм держат
   кроликов для чего-то одного.
5. **Хвосты админки** `S`. Возврат просроченной фермы в «активна» ночью
   откатывается задачей — интерфейс об этом не предупреждает. Журнал админа не
   выведен на карточку фермы (репозиторий фильтр по ферме умеет). Число ферм на
   тарифе в диалоге удаления не показано — сервер его не отдаёт.
6. **Падёж молодняка** `M` — не форма, а модель данных: крольчонок живёт числом
   внутри записи об окроле, отдельной сущности «группа в клетке» нет. При этом
   если по окролу заводили карточки крольчат, получается двойной счёт.
7. **SMS-приглашение** — требует одобренного шаблона у шлюза payom, а не кода.
   Сейчас используется единственный существующий шаблон «код подтверждения»,
   и слать им приглашение значило бы прислать человеку сообщение про код,
   которого ему никто не создавал.

## Как поднять окружение для тестов

Порт 3307 занят чужим MySQL из WSL, поэтому тестовая база живёт на 3310, а
хранилище файлов — на 9000:

```bash
docker run -d --name rabbitfarm-testdb -p 127.0.0.1:3310:3306 \
  -e MYSQL_ROOT_PASSWORD=<DB_PASSWORD> -e MYSQL_DATABASE=rabbitfarm_test \
  -e MYSQL_USER=rabbitfarm_user -e MYSQL_PASSWORD=<DB_PASSWORD> mysql:8.0
```

MinIO нужен только фото-тестам; бакет `rabbitfarm-uploads` надо создать
руками. Прогон:

```bash
DB_HOST=127.0.0.1 DB_PORT=3310 DB_NAME=rabbitfarm DB_TEST_NAME=rabbitfarm_test \
  MINIO_ENDPOINT=127.0.0.1 MINIO_PORT=9000 npx jest --runInBand --coverageThreshold='{}'
```

Форматирование Dart — только `dart format --language-version=3.6 <файл>`
поимённо: без флага форматтер переписывает файл целиком в новый стиль, и дифф
разбухает на сотни строк чистой переверстки. Прогнать форматтер по всему
проекту стоит отдельным коммитом.
